### Day 655: July 14, 2026 (Tuesday)
- NOTE FOR THE DAY:
  - Figuring out if library file is for Windows or MinGW.
    - Based on the file extension and typical naming conventions, libBigNumber.a is built for MinGW / GCC.
    - On Windows:
      - MinGW (GCC) compiles static libraries into the .a format (e.g., libBigNumber.a).- MSVC (Microsoft Visual C++) compiles static libraries into the .lib format (e.g., BigNumber.lib).
    - How to Verify the File Format ExactlyIf you want to be 100% sure or need to check other binary files in the future, you can use these methods:
    1. Check with the file Command (MSYS2, Git Bash, WSL, or Linux)If you have Git Bash, WSL, or MSYS2 installed, run:
      - C:\msys64\usr\bin\file libBigNumber.a

      - MinGW/GCC output: It will show up as a current ar archive or similar Unix-like archive.
      - Inside, the object files will typically have names ending in .o (MinGW) instead of .obj (MSVC).
    2. Check using objdump (MinGW toolchain)If you have MinGW installed, run:
      - objdump -a libBigNumber.a
      - This will print the archive header format (e.g., pe-x86-64 or pe-i386).
    3. Check using dumpbin (MSVC toolchain)If you are using the Visual Studio Developer Command Prompt, you can run:
      - dumpbin /LINKERMEMBER libBigNumber.a
      - If it is a native MSVC library or a compatible standard format, dumpbin will list the symbols. If it is an entirely incompatible archive format, dumpbin will fail or warn you about the format.      
      - The command only worked from Visual Studio 2022
        - Tools ==> Command Prompt
        - Navigate to the location of libBigNumber.a 
    - ⚠️ Important compatibility note:Even if you manage to link a .a static library in MSVC (which Visual Studio sometimes allows if you manually add it to the linker inputs), C++ static libraries compiled with GCC/MinGW cannot be linked with MSVC projects due to different name-mangling schemes and C++ Application Binary Interface (ABI) incompatibilities. If you are using MSVC, you should build the BigNumber library from source using MSVC instead of using the precompiled .a file.
